# Madang (마당)

> 내 방에서 시작해, 마당에서 함께. — **https://madang.party**

**디자인 · 코딩 · 문서**를 한 화면에서 만드는 템플릿 워크스페이스입니다.
**구글 · 깃허브 계정이나 이메일 인증**으로 로그인해 **개인 공간**에서 바로 시작하고, 팀원을 **초대하는 순간 그 템플릿만 협업 공간으로 전환**되어 여러 사람이 실시간으로 함께 작업합니다. 서로의 커서와 행동이 보이고, 모든 변경은 자동 저장됩니다.

- **데스크톱 우선** 웹앱입니다. 모바일은 별도 앱으로 출시할 예정이라 휴대폰 레이아웃은 만들지 않았습니다. (창이 좁으면 안내가 표시됩니다)
- 서버는 **클라우드플레어 Workers + Durable Objects** 하나로 운영합니다. 화면(정적 파일)과 협업 서버가 같은 주소(`madang.party`)에서 제공됩니다.

## 빠른 시작 (로컬)

```bash
npm install
cp worker/.dev.vars.example worker/.dev.vars   # 로컬 로그인 개발 모드 (인증 코드를 메일 대신 화면에 표시)
npm run dev     # 클라우드플레어 로컬 런타임(8787) + 화면(5173) → http://localhost:5173
```

로컬에서는 이메일 로그인만 쓸 수 있습니다. 개발 모드(`AUTH_DEV_MODE=1`)에서는 인증 코드가 메일 대신 로그인 화면과 터미널에 표시됩니다. 이 설정은 내 컴퓨터(127.0.0.1)로 들어온 요청에만 적용되므로 배포된 사이트에서는 켜지지 않습니다.

`npm run dev`는 `wrangler dev`로 실제 클라우드플레어와 같은 런타임(workerd)을 띄우므로, 로컬에서도 Durable Object · SQLite · WebSocket이 배포 환경과 똑같이 동작합니다. 두 개의 브라우저(또는 시크릿 창)로 열어 한쪽에서 **초대** 링크를 만들어 다른 쪽에서 열면 협업을 바로 확인할 수 있습니다.

배포와 같은 형태로 확인하려면:

```bash
npm run build                  # 화면 빌드 (client/dist)
npm run dev -w worker          # Worker가 화면 + API를 한 주소(8787)에서 제공 → http://localhost:8787
```

## 개인 공간 → 협업 공간

| | 개인 공간 | 협업 공간 |
| --- | --- | --- |
| 시작 | 로그인하면 바로 | 초대 링크를 처음 만들 때 자동 전환 |
| 저장 위치 | 이 브라우저(IndexedDB, 계정별로 따로) | 클라우드플레어 (Durable Object 저장소) + 브라우저 사본 |
| 인터넷 | 없어도 작업 가능 | 끊겨도 편집 가능, 다시 연결되면 자동 병합 |
| 기능 | 디자인·코딩·문서·비밀 노트·타임라인 | + 실시간 커서·행동 라벨·채팅·멤버/권한·따라가기 |
| 비밀 노트 | 브라우저에서 암호화해 저장 | 암호문 그대로 서버로 옮겨져 멤버끼리 실시간 공동 편집 |

- 전환은 **템플릿 단위**입니다. 혼자 쓰는 템플릿은 계속 개인 공간에 두고, 함께 쓸 템플릿만 초대하면 됩니다.
- 전환할 때 템플릿 ID·주소·브라우저 사본을 그대로 유지하므로 **작업하던 화면에서 끊김 없이** 협업 모드로 바뀝니다. 지금까지의 내용, 타임라인 기록, 비밀 노트(암호화된 상태 그대로)가 함께 올라갑니다.
- 개인 공간은 **로그인한 계정마다 따로** 저장됩니다. 같은 브라우저에서 다른 계정으로 로그인해도 서로의 개인 템플릿이 보이지 않고, 로그아웃해도 지워지지 않아 다시 로그인하면 그대로 이어집니다.
- 협업 공간은 계정에 묶여 있어 **어느 기기에서 로그인해도** 같은 템플릿 목록이 보입니다.

## 로그인

| 단계 | 내용 |
| --- | --- |
| 1. 본인 확인 | **Google · GitHub로 계속하기** 또는 **이메일로 계속하기**(6자리 인증 코드). 비밀번호는 없습니다 |
| 2. 이름 정하기 | 처음이면 사이트에서 표시될 **이름**(과 커서 색상 · 아바타)을 정합니다. 외부 계정으로 가입할 때도 같습니다 (외부 계정 이름을 미리 채워 줌) |
| 3. 시작 | 메인 화면으로 이동. 초대 링크로 왔다면 그 초대장으로 돌아갑니다 |

- 가입과 로그인은 같은 흐름입니다. 이미 계정이 있으면 2단계 없이 바로 들어갑니다.
- 같은 이메일로 확인된 외부 계정은 **하나의 계정으로 연결**됩니다. 이메일로 가입한 뒤 같은 주소의 구글 계정으로 로그인해도 같은 계정입니다.
- **로그아웃**은 오른쪽 위 프로필 메뉴에 있습니다. 로그인하지 않고 앱 주소를 열면 로그인 화면으로 가고, 로그인 후 원래 가려던 곳으로 돌아옵니다.
- 로그인 화면에는 **서버에 설정된 로그인 방법만** 나타납니다 (아래 "로그인 설정").
- 로그인 기능 이전(가입 없이 쓰던 때)에 이 브라우저에서 쓰던 **개인 공간 · 프로필 · 참여한 협업 템플릿은 처음 로그인한 계정으로 자동으로 옮겨집니다.**

보안

- 로그인은 **HttpOnly · Secure · SameSite=Lax 쿠키**(`__Host-` 접두사)로 유지되어 자바스크립트에서 읽을 수 없습니다. 서버에는 세션 토큰의 해시만 저장하며, 사용하는 동안 30일씩 연장됩니다.
- 다른 사이트에서 보낸 쓰기 요청 · 실시간 연결은 `Sec-Fetch-Site`/`Origin` 확인으로 한 번 더 막습니다.
- 인증 코드: 10분 유효 · 5번 틀리면 폐기 · 다시 받기 30초 간격 · 이메일당 시간당 8회 · IP당 시간당 20회. 코드는 해시로만 저장합니다.
- 외부 로그인: `state`(이 브라우저에 쿠키로 묶음 · 한 번만 사용) · PKCE · `nonce`로 요청 위조와 재사용을 막습니다.


## 초대 방식: 왜 "조건이 있는 초대 링크"인가

초대 방식은 네 가지를 비교해 정했습니다.

| 방식 | 장점 | 문제 |
| --- | --- | --- |
| 워크스페이스 공용 초대 코드 | 간단함 | 코드가 한 번 퍼지면 누구나 계속 들어옴 · 권한을 사람마다 다르게 줄 수 없음 · 재발급하면 아직 안 쓴 사람까지 전부 막힘 · 누가 어떤 경로로 들어왔는지 알 수 없음 · 짧은 코드는 추측 가능 |
| 이메일 초대 | 대상이 명확 | 초대받을 사람의 이메일을 알아야 함 · 카카오톡·슬랙으로 공유하는 실제 사용 흐름과 맞지 않음 · 메일 발송 한도를 초대에도 써야 함 |
| **링크마다 조건을 거는 초대 링크** ✅ | 메신저 어디로든 공유 · 링크별 권한/기간/인원/승인 · 링크 하나만 골라서 취소 | — |
| 승인 요청 | 모르는 사람 차단 | 단독으로 쓰면 번거로움 → **링크 옵션**으로 제공 |

그래서 **"링크마다 조건이 다른 초대 링크 + 선택적 승인"** 을 채택했습니다 (Figma·Notion·Slack이 쓰는 방식).

- **권한**: 편집자 / 뷰어 (뷰어는 서버에서도 쓰기가 차단되는 읽기 전용)
- **유효 기간**: 1일 · 7일(기본) · 30일 · 만료 없음
- **사용 인원**: 1명만 · 5명 · 20명 · 제한 없음
- **참여 전 승인**: 켜면 링크가 다른 곳으로 퍼져도 편집자 이상이 승인한 사람만 들어옵니다. 요청은 실시간으로 알림(토스트 · 초대 버튼/멤버 메뉴 배지)되고, 요청한 사람은 승인되는 즉시 자동으로 입장합니다. 창을 닫아도 대시보드에서 계속 확인합니다.
- **메모**: "디자인팀 단톡방"처럼 어디에 보낸 링크인지 적어 두면, 유출되었을 때 그 링크만 골라 취소할 수 있습니다.
- **보안**: 링크 토큰은 약 143비트 난수라 추측할 수 없습니다. 만료·소진·취소된 링크는 목록에서 자동으로 정리되고, 이미 참여한 멤버에게는 영향이 없습니다.
- **메신저 미리보기**: 링크를 카카오톡·슬랙 등에 붙이면 템플릿 이름·초대한 사람·권한이 미리보기 카드에 표시됩니다.
- **받는 사람**: 링크를 열면 로그인하지 않아도 초대장(템플릿·초대한 사람·권한·남은 기간)이 먼저 보이고, **로그인하고 참여하기**를 누르면 로그인(처음이면 인증 후 이름만 정하면 가입) 뒤 초대장으로 돌아와 바로 참여합니다.
- **모바일 앱 대비**: 초대는 `https://madang.party/join/<토큰>` 한 가지 형식이라, 앱 출시 후 같은 링크를 앱 딥 링크(유니버설 링크)로 받아 처리할 수 있습니다. API 주소는 `VITE_API_BASE`로 바꿀 수 있습니다.

## 클라우드플레어 배포

### 처음 한 번 설정

1. [dash.cloudflare.com](https://dash.cloudflare.com) 무료 계정을 만듭니다. (카드 등록 없이 Workers Free 요금제로 사용 가능)
2. **계정 ID** 확인: 도메인 `madang.party`의 *Overview* 페이지 아래쪽 **API** 영역에서 *Account ID* 복사 (또는 대시보드 검색창에 `Copy account ID`)
3. **API 토큰** 만들기: [Account API tokens](https://dash.cloudflare.com/?to=/:account/api-tokens) → *Create Token* → *Permission policies*의 **Custom** 목록에서 **Edit Cloudflare Workers** 선택
   - 이름: 예) `madang-github-deploy`
   - *Account resources*: 내 계정 · *Zone resources*: **Specific zone → `madang.party`**
   - *Create Token*을 누르면 토큰이 **한 번만** 표시되니 바로 복사
4. GitHub 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
   - `CLOUDFLARE_API_TOKEN` = 3번 토큰
   - `CLOUDFLARE_ACCOUNT_ID` = 2번 계정 ID
5. **Deploy to Cloudflare** 워크플로가 타입 검사 · 통합 테스트를 통과하면 자동으로 배포하고, 마지막에 `https://madang.party` 응답까지 확인합니다. `main`에 병합될 때 실행되고, Actions 탭의 *Run workflow*로 수동 배포도 할 수 있습니다.

배포가 끝나면 **https://madang.party** 에서 열립니다.

- 도메인은 `worker/wrangler.jsonc`의 `routes`에 등록되어 있어, 배포할 때 클라우드플레어가 DNS 레코드와 HTTPS 인증서를 자동으로 만듭니다. (도메인이 같은 클라우드플레어 계정에 있어야 합니다)
- 배포 중 도메인 연결 단계에서 권한 오류가 나면 대시보드 → Workers & Pages → **madang** → *Settings → Domains & Routes → Add → Custom domain*에서 `madang.party`를 한 번만 직접 추가하세요.
- `*.workers.dev` 주소는 꺼 두었습니다. 개인 공간 데이터는 브라우저에 **주소별로** 저장되므로, 주소가 둘이면 같은 사람의 작업이 나뉘어 보이기 때문입니다. `www.madang.party`는 대시보드의 *Rules → Redirect Rules*에서 `madang.party`로 넘기고 (경로 · 쿼리 유지, 301), `http://`는 *SSL/TLS → Edge Certificates → Always Use HTTPS*로 `https://`에 넘깁니다 (비밀 노트 암호화는 보안 연결에서만 동작). 동작 여부는 Actions 탭의 **Site check** 워크플로로 언제든 확인할 수 있습니다.
- D1·KV 같은 추가 리소스를 만들 필요가 없습니다. Durable Object는 첫 배포 때 자동으로 생성됩니다.

직접 배포하려면:

```bash
npx wrangler login     # 브라우저로 클라우드플레어 로그인
npm run deploy         # 화면 빌드 + wrangler deploy
```

### 로그인 설정

로그인 방법마다 필요한 값을 아래 둘 중 한 곳에 넣습니다. 값이 있는 방법만 로그인 화면에 나타납니다. 콜백 주소는 `https://madang.party/api/auth/callback/<google|github>` 형식입니다.

- **GitHub 저장소 Secrets** (*Settings → Secrets and variables → Actions*): 다음 배포 때 **Deploy to Cloudflare** 워크플로가 Worker의 Secret으로 옮깁니다 (로그에는 이름만 표시). GitHub Secret 이름은 `GITHUB_`로 시작할 수 없어서 깃허브 로그인 값은 `GIT_CLIENT_ID` · `GIT_CLIENT_SECRET`을 씁니다.
- **클라우드플레어 대시보드** → *Workers & Pages → madang → Settings → Variables and Secrets → Add* → **Type: Secret**. 저장하면 바로 적용됩니다.

배포 워크플로는 로그인 방법이 **하나도 없으면 배포를 중단**합니다 (아무도 로그인할 수 없는 상태로 바뀌지 않도록 이전 버전을 그대로 둠).

**① 이메일 인증 코드 — [Resend](https://resend.com) (무료: 하루 100통 · 한 달 3,000통)**
1. Resend 가입 → *Domains → Add Domain* → `madang.party` → 안내되는 DNS 레코드를 추가합니다. 도메인이 클라우드플레어에 있으면 *Auto configure*(클라우드플레어 로그인)로 한 번에 추가됩니다.
2. 도메인이 *Verified*가 되면 *API Keys → Create API Key* (권한: Sending access, 도메인: madang.party)
3. Secret `RESEND_API_KEY` = 발급한 키 (`re_…`)
4. (선택) `EMAIL_FROM` = 보내는 사람. 기본값 `Madang <login@madang.party>`

> 클라우드플레어 자체 메일 발송(Email Service)은 아무 주소로나 보내려면 Workers Paid(월 $5)가 필요해서, 무료로 쓸 수 있는 Resend를 기본으로 했습니다.

**② Google**
1. [Google Cloud Console](https://console.cloud.google.com) → 새 프로젝트 → *APIs & Services → OAuth consent screen*: External · 앱 이름 `Madang` · 지원 이메일 · *Authorized domains*에 `madang.party` → 준비되면 *Publish app* (기본 범위 openid·email·profile만 써서 별도 심사 없음)
2. *Credentials → Create credentials → OAuth client ID* → *Web application* → *Authorized redirect URIs*에 `https://madang.party/api/auth/callback/google`
3. Secrets `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`

**③ GitHub**
1. GitHub → *Settings → Developer settings → OAuth Apps → New OAuth App*
   - Homepage URL: `https://madang.party` · Authorization callback URL: `https://madang.party/api/auth/callback/github`
2. *Generate a new client secret*
3. Secrets `GIT_CLIENT_ID`, `GIT_CLIENT_SECRET`

### 무료 요금제에서 얼마나 쓸 수 있나 (작성 시점 기준)

| 항목 | 무료 한도 (매일 초기화) | 이 앱에서 쓰이는 곳 |
| --- | --- | --- |
| Worker 요청 | 10만 건 | API 호출(목록·초대·노트 잠금 해제 등). **화면 파일 요청은 무료·무제한** (Worker를 거치지 않음) |
| Durable Object 요청 | 10만 건 | 실시간 메시지는 **20개당 1건**으로 계산 → 하루 약 200만 메시지 |
| Durable Object 실행 시간 | 13,000 GB·초 | 메시지가 없으면 잠들어(Hibernation) 거의 쓰지 않음 |
| SQLite 저장 공간 | 계정 전체 5GB | 템플릿 문서 · 타임라인 · 채팅 · 암호화된 노트 |
| SQLite 쓰기 | 10만 행 | 편집은 2초씩 묶어 한 번에 저장 |

- 개인 공간은 서버를 전혀 쓰지 않으므로 사용량에 포함되지 않습니다.
- 사용량을 아끼는 설계 (다른 사람 화면에서는 부드럽게 보이도록 유지):
  - **혼자일 때**는 커서·텍스트 커서·화면 위치·행동 라벨을 보내지 않고, 문서 변경은 1초씩 모아 저장만 합니다. 누가 들어오면 모아 둔 정보를 바로 보냅니다.
  - **함께일 때** 문서 변경은 150ms씩 묶고(한글 조합 중 생기는 여러 변경도 한 번에), 텍스트 커서는 같은 메시지에 실어 보냅니다. 도형을 끄는 동안만 50ms로 짧게 보냅니다.
  - 마우스 커서는 100ms 간격으로 보내고, 받는 쪽에서 120ms에 걸쳐 이어 움직여 미끄러지듯 보이게 합니다.
  - 펜으로 그리는 선은 그리는 동안 문서에 쓰지 않고 **새로 생긴 점만** 80ms마다 중계하며, 받는 쪽은 도착한 점을 매 프레임 나눠 그립니다. 손을 떼면 완성된 선을 한 번만 저장합니다.
  - 25초 ping은 서버를 깨우지 않는 자동 응답 · 편집 활동 보고는 20초 간격 · 대시보드 새로고침 60초.
- 측정 결과(로컬 런타임, 한 사람이 보내는 메시지): 함께 코드 60자 입력 56 → 29건 · 마우스 이동 3초 70 → 50건 · 펜 한 획 121건/199KB → 66건/9KB · 혼자 코드 입력 56 → 8건 · 혼자 마우스 이동 70 → 0건.
- 한도를 넘으면 그날은 요청이 거절됩니다(요금이 청구되지 않음). 팀이 커지면 Workers Paid(월 $5)로 올리면 됩니다.

## PM 제안으로 추가한 기능

1. **로컬 우선(Local-first)** — 가입 없이 시작, 오프라인에서도 작업, 협업 공간도 브라우저 사본으로 즉시 열림
2. **조건부 초대 링크 + 승인 요청** — 위 설명 참고. 메신저 미리보기 카드 포함
3. **권한(소유자/편집자/뷰어)** — 권한 변경이 접속 중인 사람에게 즉시 반영, 내보내면 즉시 연결 해제
4. **따라가기(Follow)** — 팀원의 화면(위치·디자인 보드 시점)을 그대로 따라감. 발표·리뷰에 유용
5. **실시간 채팅** — 템플릿별 채팅, 읽지 않은 메시지 배지
6. **명령 팔레트(Ctrl K)** — 검색·만들기·이동, 한글 초성 검색
7. **"누가 어디 있는지"** — 레일 아이콘·탐색기 항목 옆에 보고 있는 사람, 자리 비움 감지
8. **비밀 노트 보안** — 5회 실패 시 5분 잠금, 10분 무활동 자동 잠금, 비밀번호 변경 시 새 키로 재암호화 + 열람자 강제 잠금, 실패 기록
9. **시작 프리셋**, **다크/라이트 테마**, **키보드 단축키**(`?`로 도움말)

## 아키텍처

```
브라우저 (React + Vite)                              클라우드플레어 Worker (한 주소)
 ├─ 개인 공간: IndexedDB                              ├─ 정적 파일(client/dist) — Worker를 거치지 않고 바로 응답
 │   ├─ 템플릿 문서(Y.Doc) · 타임라인                  ├─ /api/*   REST + 실시간 연결 라우팅
 │   └─ 비밀 노트(암호문)                             └─ /join/*  초대 링크 미리보기 카드(OG 태그)
 ├─ 협업 공간: WebSocket 1개 ──────────────────▶  Durable Object "TemplateRoom" (템플릿마다 1개)
 │   ├─ 문서 동기화(상태 벡터 교환 + 변경 중계)           ├─ Yjs 문서: 메모리 병합 → 2초마다 SQLite 저장, 60개 쌓이면 압축
 │   ├─ 커서 · 보고 있는 화면 · 행동 라벨                 ├─ 타임라인(5분 병합) · 토스트 · 채팅
 │   ├─ 채팅 · 타임라인 · 토스트                         ├─ 비밀 노트: 암호문·확인값 해시만 보관/중계
 │   └─ 비밀 노트(암호화된 변경만 주고받음)                └─ WebSocket Hibernation (조용하면 잠듦)
 └─ CodeMirror 6 · TipTap 3 · SVG 캔버스           Durable Object "Directory" (1개)
                                                     └─ 계정 · 로그인(세션 · 인증 코드 · 외부 계정) · 협업 템플릿 · 멤버/권한 · 초대 링크 · 참여 요청
```

- **동기화**: 연결될 때마다 상태 벡터를 교환해 서로 없는 부분만 주고받습니다(오프라인 편집 자동 병합). 이후 변경은 60ms씩 묶어 보내고, 서버 확인(ack)으로 "저장됨"을 표시합니다.
- **저장**: 방(Durable Object)은 변경을 메모리에서 병합하고 2초마다 SQLite에 한 줄로 저장합니다. 값 하나가 2MB를 넘으면 나눠 저장합니다. 모두 나가면 즉시 저장합니다.
- **권한**: 모든 문서 쓰기는 방이 연결별 권한을 확인합니다. 권한이 바뀌면 접속 중인 연결에도 즉시 반영됩니다.

### 비밀 노트 (종단 간 암호화)

- 비밀번호는 어디에도 저장되지 않습니다. 브라우저에서 **PBKDF2-SHA256(60만 회)** 로 512비트를 만들어 앞 256비트는 **AES-256-GCM 키**, 뒤 256비트는 **확인값**으로 씁니다.
- 서버는 `SHA-256(확인값)`만 저장해 비밀번호가 맞는지 확인하고 30분짜리 열람 티켓을 발급합니다. 키는 브라우저 메모리에만 있어 **서버·클라우드 운영자도 내용을 읽을 수 없습니다.**
- 공동 편집은 **암호화된 변경분**만 서버를 통해 중계하고, 일정 개수마다 암호화된 스냅샷으로 합칩니다. 암호문은 노트 ID에 묶여(AAD) 다른 노트로 바꿔치기할 수 없습니다.
- 비밀번호를 바꾸면 내용을 새 키로 다시 암호화하고, 열어 둔 사람은 모두 잠깁니다.

### 코드 실행 격리

팀원이 작성한 JavaScript는 `sandbox="allow-scripts"` iframe(origin 없음) 안의 Web Worker에서 실행됩니다. 이 앱의 IndexedDB·localStorage·토큰에 접근할 수 없고, 5초 후 강제 종료됩니다.

## 알려진 한계와 다음 단계

- **개인 공간 데이터**: 브라우저에만 있으므로 브라우저 데이터를 지우면 사라집니다. 중요한 템플릿은 협업 공간으로 전환하면 클라우드에 보관됩니다. 다음 단계로 개인 공간 백업(파일 내보내기/가져오기)을 제안합니다.
- **로그인**: 외부 로그인(구글·깃허브)은 배포된 주소에서만 동작합니다 (로컬은 이메일 개발 모드). 인증 메일은 Resend 무료 한도(하루 100통)를 넘으면 그날은 보내지 못하니, 사용자가 늘면 유료 요금제나 클라우드플레어 Email Service로 옮기세요. 모바일 앱은 같은 로그인 API를 쓰되 앱 전용 로그인 흐름(딥 링크)을 추가해야 합니다.
- **알림 범위**: 실시간 알림은 열어 둔 템플릿 기준입니다. 대시보드는 60초마다(또는 창으로 돌아올 때) 목록·접속자·참여 요청 수를 새로 고칩니다.
- **실행 가능한 언어**: 브라우저에서 실행되는 것은 JavaScript와 HTML 미리보기입니다. Python 등은 Pyodide 연동이 다음 후보입니다.
- **추가 로드맵**: 버전 스냅샷/복원, 디자인 코멘트 핀, @멘션 알림, 이미지 업로드(R2).
