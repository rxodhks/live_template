# 공지사항 쓰는 법

이 폴더의 `.md` 파일 하나가 공지 한 건입니다. main에 머지하면 자동으로 배포되어
사이트의 공지사항 페이지(`/notices`) · 상단 새 소식 · (중요하면) 홈 배너에 나옵니다.

## 파일 이름

`2026-10-12-server-check.md` 처럼 날짜와 영어 소문자 · 숫자 · `-` 로 짓습니다.
파일 이름이 공지 주소가 됩니다 (`/notices/2026-10-12-server-check`).

## 형식

```
---
title: 10월 12일 새벽 서버 점검 안내
date: 2026-10-08
tag: 점검
pin: true
until: 2026-10-12
summary: 새벽 2시부터 약 1시간 동안 저장이 잠시 멈춰요
---
본문은 마크다운으로 씁니다. **굵게**, 목록, [링크](https://madang.party) 등.
```

| 항목 | 필수 | 설명 |
| --- | --- | --- |
| `title` | 예 | 제목 |
| `date` | 예 | 게시일. 미래 날짜로 두면 그날(한국 시간)부터 보입니다 (예약 게시) |
| `tag` | 아니요 | `중요` · `점검` · `새 기능` · `정책` · `소식` 중 하나 (기본 `소식`) |
| `pin` | 아니요 | `true` 면 홈 위쪽 배너로 띄웁니다. 꼭 알려야 할 공지에만 씁니다 |
| `until` | 아니요 | 배너를 이날까지만 띄웁니다 (공지 글은 계속 남습니다) |
| `summary` | 아니요 | 새 소식 · 배너에 보일 한 줄. 없으면 본문 첫 문단을 씁니다 |

형식이 틀리면 빌드(CI)가 실패하고 어디가 틀렸는지 알려 줍니다.

## 예약 업데이트 (정해진 시간에 배포)

사람들이 덜 쓰는 시간에 업데이트하려면, 바꾼 코드와 **공지 파일을 한 PR에 함께** 올리고 글 머리에 `deploy_at`을 적습니다.

```
---
title: 10월 12일 오후 2시 편집기 업데이트
date: 2026-10-08
tag: 점검
deploy_at: 2026-10-12 14:00
---
업데이트 내용 …
```

| 항목 | 설명 |
| --- | --- |
| `deploy_at` | 업데이트할 시간 (한국 시간, `2026-10-12 14:00` 형식) |
| `deployed_at` | 업데이트를 마친 시간. **직접 쓰지 않습니다** (자동으로 적힘) |

PR을 열어 두면(초안이 아닌 상태) **예약 업데이트** 워크플로(15분마다)가 알아서 진행합니다.

1. **시간 전**: 공지 파일만 먼저 main에 올려 배포 → 사이트에 "10월 12일 14:00 업데이트 예정" 공지 (홈 배너 · 새 소식)
2. **시간이 지나면**: PR의 CI가 모두 통과했고 충돌이 없으면 PR을 합치고 배포
3. **배포가 성공하면**: 공지에 `deployed_at`을 적고 다시 배포 → 같은 공지가 "업데이트 완료"로 바뀌고 새 소식으로 다시 알림

- CI 실패 · 충돌이 있으면 합치지 않고 PR에 댓글로 알립니다. 고쳐서 push하면 다음 실행 때 다시 시도합니다.
- GitHub 예약 실행은 몇 분 ~ 30분쯤 늦을 수 있습니다.
- 예약을 취소하려면 PR을 초안(Convert to draft)으로 바꾸거나 `deploy_at` 줄을 지웁니다. 이미 올라간 예정 공지는 main의 파일을 고치거나 지웁니다.
- 바로 실행해 보려면 Actions → 예약 업데이트 → Run workflow (dry run을 고르면 확인만 합니다).
- `date`는 예정 공지를 보여 줄 날(보통 오늘)로 둡니다. 미래로 두면 예정 공지도 그날부터 보입니다.

## 확인

- 로컬: `npm run dev` 후 http://localhost:5173/notices
- 예약 게시한 글도 `notices.json` 파일에는 들어 있으니, 아직 알리면 안 되는 내용은 그날 머지하세요.
